RetroArchV for PlayStation 4

Emulation on a jailbroken console, running Vulkan through RADV and OpenGL ES through zink. 113 cores, built for this hardware.

Quit from inside the application, not from the console. Use RetroArch's own Quit RetroArch entry, or the Quit combo on the pad. It returns to the console's menu with no dialog. Earlier versions showed CE-34878-0 here; they ended by returning from main(), which takes the process down outside the path the system expects.

Closing it the console's way instead — the PS button, then Close Application — still shows CE-34878-0. The console returns to its menu and nothing needs restarting, but the application is killed outright there and never gets to shut itself down, so Quit is the better habit.

Install

  1. Copy the .pkg to /data/pkg on the console over FTP.
  2. On the console: Settings → Debug Settings → Package Installer.
  3. Pick the package and install it.
  4. Launch RetroArchV.

Tested on firmware 11.00 with GoldHEN 2.4b18.10, by SiSTRo. Other firmware and other jailbreak builds may work — nobody has checked, and a report either way is useful.

It installs under its own title id, RTRV00001, so it sits beside any RetroArch already on the console rather than replacing it — the system decides collisions by title id, not by the name on screen.

First run

Online Updater → Update Core Info Files. Do this before browsing the core list. Core metadata is not shipped inside the package, so until those files arrive the downloader lists .prx filenames instead of names like “Nintendo 64 (Mupen64Plus-Next)”. Everything works either way; only the labels are missing.

With a console that has no network

Download the archive above on another machine, unzip it, and copy the .prx files into /data/retroarch/cores over FTP. Nothing else is needed — the core list is read from that directory at startup.

Copy them, do not extract them on the console. A file arriving over FTP is created executable, which is what the module loader requires. Files unpacked by other routes may not be, and a core without that bit fails to load with no explanation beyond “Failed to open libretro core”.

Core metadata works the same way offline: the .info files live in /data/retroarch/info and can be copied across from libretro's bundle.

Where everything lives

All of it sits under /data/retroarch/, which is writable and survives reinstalling the package. Put files there over FTP and RetroArch finds them at startup — there is no import step.

Edit the configuration with RetroArch closed. It keeps its settings in memory and writes the whole file out when it exits, so a change made over FTP while it is running is overwritten on quit — not merged, replaced.

The package itself is mounted read-only at /app0 and holds only the executable, the icon and the certificate bundle. Nothing there needs editing, and nothing there can be.

Configuring it

Once the cores are in place, this is ordinary RetroArch. Controller mapping, shaders, overlays, per-core options, save states, rewind, netplay's absence, the scanner, playlists — all of it behaves as it does everywhere else, with the same menus in the same places. The libretro documentation applies unchanged, and so does any guide written for another platform.

Two habits worth having early: Load Content scans a directory for anything a core claims, and per-core settings live under Quick Menu → Options while the game is running, saved with Manage Core Options.

Known limits

  • Closing the application from the console's own menu still shows CE-34878-0. It is cosmetic — the console recovers on its own. Quit from inside RetroArch does not.
  • 63 of the 164 cores in the build recipe do not compile for this platform yet. The ones listed here are the ones that link and export a working entry point.
  • Cores are built from upstream's tip on the day the build ran, so a core's version is a date rather than a release number.

Recommended settings

Most cores run well on their defaults. These are the exceptions: options whose default was chosen for a desktop computer and is wrong on this console, or that a game here was found to need. Change them under Quick Menu → Options while a game is running, and keep them with Manage Core Options → Save Core Options.
